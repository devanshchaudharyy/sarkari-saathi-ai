# Hindi / English localization

Implemented 18 October 2026. Scope is the existing Phases 1–5 app; AI assistance, RAG, recommendations and deployment remain outside this phase. The catalog, eligibility-rule and checklist review dates remain 8 October 2026. Translating their text does not constitute another policy review or government endorsement.

## Architecture

`client/src/i18n/core.js` supplies a pure translator factory, strict `en`/`hi` preference normalization and a finite Hindi-search alias map. `hi.json` contains project-authored display mappings keyed by original English copy. Static messages use exact keys; dynamic sentences use numbered placeholders and a compiled, escaped matching table. Explicit interpolation allows Hindi word order to differ from English. Prototype keys are not interpreted as dictionary or search entries. Numbers, booleans, React nodes and unknown text pass through unchanged. React escapes displayed strings; no HTML injection or DOM-text rewriting is used.

`useLanguage.js` exposes a small external store through React's `useSyncExternalStore`, returning `language`, `locale`, `t`, `setLanguage`, loading state and load error. Stable translation callbacks read the current language when invoked, including callbacks retained by authentication interceptors. Components subscribe without changing keys or remounting their forms. Language changes do not refetch private profile/catalog data or reset component state. Unsubscribed listeners are removed by React. An increasing request counter prevents an old asynchronous language load from overwriting a later selection.

English is available immediately. Hindi is loaded with a dynamic import; no dictionary request is made for a fresh English visit. A stored Hindi preference loads the chunk at startup and updates `<html lang>` when ready; a brief English fallback can occur while it loads. A failed chunk leaves English usable and asks the user to reload. Changing the preference does not require or expose an external API key.

Only the language code is persisted under `sarkarisaathi.language.v1`. Unsupported values fall back to English, storage failures retain in-memory usability and `storage` events synchronize other tabs. Signing out clears authentication independently and keeps language preference. User names, emails, passwords, typed districts and other input values are never translated or copied into this preference.

## UI and data boundaries

The same switcher appears in public navigation, authentication pages and the private workspace. Native button/menu semantics, selected radio-menu state, arrows, Home/End, Enter/Space, Escape, Tab/outside-focus closure and trigger focus restoration are provided. The accessible name includes the visible language text. Notifications use the language at creation; already-visible timed notifications can retain their earlier language until dismissed.

Manrope remains the Latin font. Fontsource Noto Sans Devanagari is self-hosted for Hindi, with 400/500/600/700 weights and appropriate line heights. CSS respects reduced motion and gives long Hindi controls room on small screens. Source links and brands/acronyms retain their original form. Hindi views carry a note that this is a project translation, not an official government translation. Users can return to English without losing their state.

API responses and validation contracts remain English/canonical. Translations apply at display boundaries. Option labels can be Hindi, while explicit values remain `Uttar Pradesh`, `Kerala`, `student`, `insurance`, and the existing stage/task IDs. No language field, collection, migration or database write is added. Existing saved profile and readiness records remain compatible. The Postman collection is unchanged.

Hindi search uses the finite aliases in `canonicalSearch`, including the six names and common terms such as `किसान`, `सुरक्षा`, `जीवन`, `पेंशन`, `जन धन` and `कन्या`. The typed query stays in the URL and form; the API receives the mapped canonical search. Arbitrary other queries keep literal catalog-search behavior. This is not machine translation or semantic search. Filters, browser history, selected-scheme queries and native source anchors retain their original behavior. Lists stay ordered by the original English scheme name; the Hindi sort label says so.

## Maintenance and verification

1. Add or change reviewed English copy in its owning component/data/rule/template file. Add the corresponding Hindi mapping; preserve amounts, conditions, negations, qualifications and source URLs. Review both renderings in context.
2. Keep identifiers, option values, user input and request bodies canonical. Interpolate values; do not translate an entire user record or arbitrary URL. Use own-key lookup for untrusted fallback strings.
3. For dynamic messages, keep numbered placeholders in both languages. Translate the sentence, including word order, rather than concatenating English fragments where order matters. For dates use the hook's locale and the existing time zone.
4. Run `npm run test:i18n`, the affected API suite, `npm run test:language-browser` and `npm run build`. Translation tests cover all six editorial records, all states/occupations, screening questions and sample outcomes, and every readiness task. These tests verify coverage and contracts; they do not independently establish linguistic or policy accuracy.
5. If layout/control copy changes, recheck the seven required widths and keyboard/reduced-motion behavior. Audit the production build separately from parallel browser runs.
6. Regenerate English screenshots with `npm run screenshots`; in PowerShell set `$env:SCREENSHOT_LANGUAGE='hi'`, run it again, then `Remove-Item Env:SCREENSHOT_LANGUAGE` for Hindi captures. Only synthetic demo information is used.

Unknown future editorial text and unexpected technical validation messages fall back to their English originals. Translations are project-maintained and have not been independently certified by a government body or professional translator. Confirm current requirements at the official provider; switching language never changes a screening decision or turns checklist progress into verified approval.
