# Catalog provenance and review

The initial six records were reviewed during implementation on **8 October 2026**. Sources are government department/scheme pages and a ministry statement hosted by PIB. Content is paraphrased into short editorial summaries; there are no scraped government logos, invented schemes, personalised eligibility claims or unofficial application intermediaries. This review is not government approval or an independent human-editor certification.

`server/src/data/schemes.js` is the canonical editorial source. Each record contains a stable slug, category, administering department, central/state coverage, brief benefits, audience overview, suggested next steps, caveats, HTTPS official website, reference URLs and review date. MongoDB stores copies populated by `npm run seed:schemes`. A review date means the summary was checked during implementation, not that the original source was newly published on that date or that the source can never change.

## Evidence and access limits

PM-KISAN’s ministry statement, DFS PMSBY/PMJJBY/APY overviews and the UP eligibility page were readable directly through the research tool. Full official PMJDY scheme details, DFS enrolment FAQs, the annual-report pension section, and the UP stage table were also returned in official-source search-index extracts. Some direct fetches timed out or returned gateway errors; an earlier annual-report beta URL returned 404 and was replaced with the department’s indexed current URL. No third-party blog was used as the factual authority. Source content was reviewed; continuous reachability and application availability were not certified.

The UP eligibility page carried a notice of portal maintenance for 8–9 October 2026. That dated notice was not stored as a permanent scheme rule. The UI instead warns that the official provider may be unavailable during maintenance. Direct scheme portals and PDFs are controlled by their providers and can move or become unavailable. Browser verification checks reference destinations, HTTPS government domains, new-tab behavior and safe link attributes; it does not assert that every external government page returns HTTP 200.

General next-step wording is editorial guidance to consult the official provider, not a substitute for an application manual. No complete document checklist, current deadline, individual entitlement or application approval is asserted. Monetary figures are accompanied by their conditions and official references. The catalog includes five central schemes and one Uttar Pradesh scheme; it does not imply comprehensive national or state coverage.

## Maintaining the catalog

1. Open the official departmental information and current guidelines/FAQs; resolve conflicting or older terms using the responsible authority’s current guidance. If evidence cannot be established, omit the unsupported claim or withhold the entry.
2. Update the editorial record and reference URLs together. Set `reviewedAt` only after checking content; do not generate a new date merely because the seed command runs. Put a publication date in a reference title only when known from the source.
3. Keep summaries brief. Include exclusions/caveats and distinguish support, insurance and repayable credit. Never convert profile fields into an eligibility result in this phase.
4. Run `npm run seed:schemes`, API tests and scheme browser tests. Compare rendered details against the source, inspect mobile layouts and external-link destinations.

The seed does not delete unrelated records. Retiring an entry requires an intentional database/editorial operation; there is no public/admin editing endpoint or scheduled source sync in this phase. Search is a bounded literal substring over editorial names, acronyms, summaries and keywords; it is not semantic search or AI.
