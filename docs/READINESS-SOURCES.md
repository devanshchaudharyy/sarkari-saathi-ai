# Preparation checklist sources and maintenance

Editorial review: **8 October 2026**. Local implementation verification: **9 October 2026**. Template version: `2026-10-08.1`, in `server/src/domain/readiness.js`. Review dates describe our review, not government publication dates or endorsement.

These are partial, source-linked preparation tasks for six schemes. They are not a complete mandatory document list, an eligibility decision or a verified application. A checked item means the user considers that task prepared. No source establishes that checking every task guarantees acceptance. Every template ends by asking the user to confirm current requirements with the provider.

Research used primary government/regulator sources only. PFRDA's FAQ and the PIB guidance were read directly. Official indexed material supplemented sources where direct access was unavailable, including the PMJJBY page and UP guide. Direct external availability is not guaranteed. Indexed evidence was used conservatively to describe preparation topics, not to reconstruct a complete current form or infer an unsupported universal requirement.

PMJDY does not claim everyone must supply Aadhaar or every example identity document; the bank must identify the applicable KYC route. PM-KISAN's state-government guidance supports preparation topics, not a claim that one state's full document procedure applies nationally. UP's [presentation](https://mksy.up.gov.in/women_welfare/pdf/MKSY-Presentation.pdf) and [government orders](https://mksy.up.gov.in/women_welfare/gov_orders.php) show stage-specific evidence and procedure revisions. The app intentionally asks users to consult the current stage and circumstance requirements instead of presenting older documents as a universal complete list. Checking an insurance consent task does not authorise payment.

## Maintenance procedure

1. Reopen the official provider/regulator sources and current forms/orders. Check stage, KYC and family exceptions; record direct-access limitations.
2. Update task wording and source links only for supported facts. Keep stable IDs for unchanged concepts; add/remove IDs when the concept changes. Do not add uploads, identity numbers or arbitrary notes to this feature.
3. Advance `READINESS_VERSION` and `READINESS_REVIEWED_AT` after a substantive review, and update these notes. The current global version conservatively invalidates prior marks across templates.
4. Run backend readiness tests, the browser readiness suite and the production build. Recheck layout and accessibility if copy or controls change.

GET with a changed version shows all tasks unmarked and a review notice without changing the stored row. The next valid confirmed task mutation replaces old-version marks with the newly confirmed item and advances the version. Unknown or removed task IDs never inflate progress. New catalog entries without reviewed templates display no tasks and 0% completion. Saved entries removed from the catalog retain an explicitly unavailable removable entry, not a cached invented checklist.

No live scraping, automatic official-change alerting, independent document verification or government integration is implemented. The project is independent and is not an official government service.
